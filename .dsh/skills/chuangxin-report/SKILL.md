## 硬格式（格式细则见独立 skill `chuangxin-format`）

本 skill 只管**内容体例**；排版格式（字号、图表标题、三线表、参考文献格式、英文摘要、页边距等）全部走项目级 skill `chuangxin-format`，不在本文件重复。写报告或 PPT 时加载它，并按其「交稿前格式自查」逐条检查。

最硬的 4 条（课程模板原文，任何情况下不能破）：

- 标题：黑体四号加粗，序号 `1 / 1.1 / 1.1.1 /（1）/ ①`
- 正文：宋体小四，1.2 倍行距
- 图标题在图下居中、黑体五号；表标题在表上居中、黑体五号
- 结构页顺序：封面 → 课程报告要求（照抄原文）→ 团队分工情况说明 → 一、课程报告 → ……（理论课再加二、PPT / 三、学习总结 / 四、成绩评价；实践课只有一、课程报告 → 二、成绩评价）

评价构成：平时 20%（考勤+课堂表现）、课程设计成果展示 40%（格式规范/思路清晰/表达流畅/**图文并茂**/**数据详实**）、汇报答辩 40%。每个成员单独一张评价表。

## 理论课报告骨架（3 项任务，缺一项即不合格）

课程要求原文的落点：**宏观 PESTN → 中观 6 力 → 微观用户 → 定位结论**，再产品，再商业模式。

```
一、课程报告
1 市场分析和项目选择
  1.1 PESTN 分析（政治/经济/社会/技术/自然环境，每节 1-2 组统计数据）
  1.2 中观环境：6 力模型（现有竞争者、潜在进入者、替代品、供应商、购买者、互补/利益相关方）

  1.5 市场细分与目标市场选择
  1.6 竞争者分析（四类方案对比表）
  1.7 用户画像与痛点（生产端/使用端分开写）

2 产品服务创新设计
  2.1 概述（一句话说清"给谁、解决什么、凭什么"）
  2.2 功能架构 + 技术架构（各一张分层图）
  2.3 关键核心技术及创新点（3-4 个，每个"痛点→方法→指标"）
  2.4 项目展示（UI 界面截图 + 硬件外观/实物图）
3 商业模式设计（画布 9 要素必须齐全）
  3.1 客户细分 3.2 价值主张 3.3 渠道通路 3.4 客户关系 3.5 收入来源
  3.6 核心资源 3.7 关键业务 3.8 重要合作 3.9 成本结构
```

## 实践课报告骨架（参照专利申报书）

课程要求 7 条，对应到专利体例：

| 课程要求 | 落到的章节 |
|---|---|
| 项目需求分析 | 背景技术（应用场景 + 用户痛点 + 数据） |
| 项目技术分析 | 背景技术（现有技术方案 + 缺陷，逐条列） |
| 项目目标 | 发明内容（名称、目的、解决的痛点、弥补的缺陷） |
| 项目方案和具体实例 | 具体实施方式（分步骤、带公式/伪代码） |
| 关键核心技术及创新点 | 创新点 3-4 条 + 有益效果 |
| 项目效果 | 实际测试 / 仿真预测 / 预估（必须有数据） |
| 项目附图 | 技术路线图、流程图、界面、硬件外观 |

范本 2 的做法值得照抄：正文**加专利行号（5/10/15/20）与说明书页码**，末尾附"说明书附图 图1~图6"，再补一节"核心竞争力"（四段式）。范本 1 的做法：没有整机时用 **Arduino 小型模拟系统**验证核心机理（代码 + 接线表 + 串口日志），这叫"硬件小样 + 软件大样"。

## 从两份范本学到的 12 个加分招式

1. **数据密度**：每个判断后面挂数字和出处。范本 2 的财务章能算出折现率 14.89%（国债 4.27% + CAPM）、NPV 1306 万、IRR 52.36%、回收期 2.52/2.99 年。
2. **三阶段叙事**：初创期/成长期/成熟期贯穿经营模式、盈利模式、营销策略、组织结构、融资计划。这是范本 2 的骨架，评委会觉得"想清楚了"。
3. **痛点-方法-指标闭环**：每段技术描述写成"现有方案在 X 场景做不到 Y（缺陷）→ 我们采用 Z → 达到 N（可测指标）"。
4. **图文并茂是硬指标**：平均每 2-3 段一张图或表，且每张都被正文引用（"如图 1-1 所示"）。
5. **真实交付物**：能跑的原型 > 效果图。范本 1 放了 Axure 五个页面（主页面/商城/我的农田/社区/更多）可交互链接 + 实物照片。
6. **外部背书**：专利（申请号）、企业适用证明、合作意向书。有就写，没有就写"已提交/拟申请"。
7. **核心竞争力四点式**：高可靠 / 快部署 / 低成本 / 易移植，每条一段，带横向对比。
8. **公司化包装**：起公司名、写使命/愿景/口号/定位（范本 2：武汉森然骏行；"复刻世界，定位未来"）。
9. **市场容量自下而上算**：存量设备数 × 替换率 × 单价，而不是只贴行业报告总量。
10. **商业模式分层**：范本 1 用五要素，范本 2 用"产学研创深度融合 + 三阶段经营 + 盈利模式表"。课程要 9 要素，两者都要覆盖到。
11. **分工写能力不写任务**："负责方案实现与核心技术提出实现 / 背景技术落实与技术缺陷统筹 / 应用场景与成本预算可行性 / 仿真预测与实际测试 / 附图绘制"。
12. **报告厚度**：理论课 60-85 页、实践课 25-30 页，是这两份范本的共同水位。低于这个量级基本拿不到 40% 的过程分。

## 本项目弹药库（写的时候直接取用）

核心事实见 [project-ammo.md](references/project-ammo.md)，要点：

- 项目名：**基于CA注意力机制的绝缘子缺陷检测自主巡检机器人**（2026 大创 & "理工创新智链"基金）
- 团队：蔡羽凡（负责人，机器人工程）、何周俣（电气工程及其自动化，本 skill 使用者）；自动化学院
- **分工边界（重要）**：本 skill 使用者何周俣只负责 **视觉 + 决策** 两个软件模块——视觉 = 绝缘子缺陷检测（CA 注意力 + YOLO），决策 = 导航路径规划与避障（平滑优化 A* + DWA）。**不承担硬件**，写报告时硬件只作系统架构背景一笔带过，不展开选型/联调/装配。
- 技术重心：CA 坐标注意力 + YOLO 检测（mAP≥95%）、轻量化边缘部署（延迟<200ms）、平滑优化 A* 引导 DWA 导航（避障<300ms、厘米级定位）
- 市场：110kV 以上变电站 35,900 座；室外轮式需求 36,503 台 × 50-80 万 ≈ 180-290 亿；室内导轨 40,645 台 × 30-60 万 ≈ 120-240 亿；单台替代 4-6 人，年省 48 万
- 竞品四类：AI 摄像头、无人机、四足机器人、红外-超声——各有明确缺陷，正好做 6 力与竞品对比表

## 常见错误

- 把"理论课"写成实践课（理论课要商业与市场，实践课要技术与专利体例，别混）
- PEST 只写空话没有数字；6 力模型漏掉或硬凑
- 创新点写成"用了深度学习"，没有对比与指标
- 项目展示放网图/渲染图，没有自测数据
- 直接复制范本段落——两份范本都是别人的项目，只能学结构不能抄内容
