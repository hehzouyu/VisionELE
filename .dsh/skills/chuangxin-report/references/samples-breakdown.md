### 硬格式（两份通用）

| 项 | 规定 |
|---|---|
| 标题 | 黑体四号加粗 |
| 正文 | 宋体小四 |
| 行距 | 1.2 倍 |
| 图题 | 图下方居中，黑体五号，编号「图 1-1」 |
| 表题 | 表上方居中，黑体五号，编号「表 1-1」 |
| 序号 | 1 → 1.1 → 1.1.1 →（1）→ ① |
| 评价 | 平时 20% + 成果展示 40% + 汇报答辩 40% |

成果展示评分细则原文：「格式规范、思路清晰、表达流畅、图文并茂、数据详实；成果展示包括界面设计、软文作品、实际运作成果等」。
答辩评分细则原文：「思路明确，有自我思考；PPT 层次分明，重点突出；表达流畅，逻辑关联清晰」。

## 二、范本 1：掌上农场—实时检测系统（产品路线）

三份文件：`掌上农场（ppt）.pdf`（p1）、`掌上农场（实践课）.pdf`（p2，约 25 页）、`掌上农场（理论课）.pdf`（p3，约 60 页）。另有 Axure 导出的可交互原型 `UI掌上农场/`。

### 项目设定
- 面向大棚种植户的土壤温湿度实时检测 + 线上商城。
- 硬件 3 类传感器：DHT11 温湿度、YL-69 土壤湿度、LDR 光敏；Arduino Uno 做「小型模拟系统」。
- 六大功能：数据采集 → 手机端实时显示 → 异常报警 → 历史数据 → 专家建议 → 商城。

### 理论课结构（一、课程报告）

```
1 市场分析和项目选择
  1.1 PEST 分析（政治/经济/社会/科技，每节配统计数据 + 柱状图）
  1.2 市场发展趋势
  1.3 需求分析（1.3.1 规模 / 1.3.2 结构 / 1.3.3 特点 / 1.3.4 预测）
  1.4 市场定位（美国→日本→中国时间线）
  1.5 市场细分（按经济水平分高中低端）
  1.6 应用场景（大棚环境示意图）
  1.7 用户需求与痛点（生产端/使用端分开）
2 产品服务创新设计
  2.1 产品服务概述
  2.2 功能架构（图 1）/技术架构（图 2）
  2.3 关键核心技术及创新点
     2.3.1 多种场景共同适用（模块化拆分：主控/土壤/环境/光照/定位）
     2.3.2 共享植物成长信息
     2.3.3 较低的制造成本（对比市面 2000-5000 元，自研 500-800 元）
     2.3.4 双重秒级操控（OneNET 云端 + 仿真真实大棚）
  2.4 项目展示（2.4.1 UI 交互简述 / 2.4.2 UI 界面设计，配截图）
3 商业模式设计
  3.1 商业五要素（客户细分/价值主张/渠道/客户关系/盈利）
  3.2 具体分析（价格策略 + 促销策略 + 市场推广）
  3.3 收益和成本（成本四类：硬件/软件/运营/市场；盈亏平衡 300 套）
三、课程学习总结
四、成绩评价
```

**这套骨架的强项**：每一步都有数字（大棚面积 3796.98 万公顷、智能设备渗透率不足 10%、定价 99 元/年）和图表（PEST 四节各一张柱状图）。
**它的不足**：PEST 缺“自然”（PESTN 的 N），6 力模型没写，商业模式只有五要素没到九要素。范本自己也没完全按模板，但老师给了高分——说明**结构密度比死抠条目更重要**。

### 实践课结构（专利式但偏产品报告）

```
1.1 技术背景（现有两方案缺陷 + 技术路线图）
1.2 核心技术
  1.2.1 技术创新点 1（多环境自动调控）
  1.2.2 技术创新点 2（数据共享，含对比表）
  1.2.3 技术创新点 3（低成本——芯片/传输/模块价格表）
  1.2.4 技术创新点 4（双重秒级——数据流图）
2.1 用户需求（4 条需求 + 图链）
2.2 应用场景（场景对比）
2.3 项目优势（科学性/领先性/独特性/实用性）
3.1 硬件小型模拟系统（Arduino 代码清单 + 引脚接线表 + 串口日志 + 实物照片）★核心加分项
3.2 软件平台界面（UI 设计说明）
```

**范本 1 最大的启发**：没有整机也能交实践课——用 **Arduino 小型模拟系统**把“检测→报警”核心链路真实跑通，附完整代码、接线表、串口输出和实物照片，再配 Axure 可交互原型。这就是课程要的“实际运作成果”。

### Axure 原型（可选但极加分）
`UI掌上农场/` 下 `start.html`、`主页面.html`、`商城.html`、`我的农田.html`、`掌上农场.html`、`更多.html`、`社区.html` + `data/`、`files/`、`images/`、`plugins/`、`resources/` 目录。**理论课“项目展示”直接放可点开的原型链接，而不是截图。**

## 三、范本 2：智行未来—高精度建图定位专家（技术+商业路线）

### 项目设定
- 激光 SLAM 高精度建图定位方案，公司化包装：武汉森然骏行科技有限公司，官网 www.jzhx.com，使命「让测绘更高效更智能」、愿景「以数智融合助推智慧中国」、口号「复刻世界，定位未来」。

## 四、两份范本的对比与选择

| 维度 | 范本 1 掌上农场 | 范本 2 智行未来 |
|---|---|---|
| 路线 | 产品/用户体验 | 技术/专利 + 商业计划书 |
| 理论课体量 | ~60 页 | ~80 页 |
| 实践课体例 | 产品报告（专利宽松） | 专利说明书（严格） |
| 技术深度 | 传感器 + Arduino 小样 | SLAM 算法 + 仿真 |
| 商业深度 | 五要素 + 盈亏平衡 | 11 章 + 三表 + NPV/IRR |
| 最大亮点 | Axure 可交互原型 + 实物 | 专利体例 + 完整财务模型 |
| 适合什么项目 | 应用型、体验型 | 算法型、硬科技 |

**给本项目的建议**：巡检机器人属于“算法 + 硬件”型，走**范本 2 的骨架 + 范本 1 的交付物**：
- 理论课用范本 2 的 11 章结构（但把市场分析扩到 PESTN/6 力/用户三层，因为模板要求）
- 实践课用范本 2 的专利体例 + 范本 1 的“小样验证”思路（没有整机就跑算法仿真 + 数据集实验）
- 项目展示放 UI 原型 + 算法效果图（检测框、注意力热力图、路径规划图）

## 五、两份范本共同踩过的坑（别学）

1. 范本 1 实践课章节编号混乱（两个 `1.2`）、范本 2 实践课有整段英文引用未汉化——**范本也不是满分卷**，学结构不学排版错误。
2. 范本 1 理论课 PEST 只有 4 个（缺自然），范本 2 理论课竞品部分较弱。
3. 两份范本的参考文献都不规范（范本 2 直接放英文网页链接）。需要时补知网文献。
4. 范本 2 的“企业适用证明”“合作意向书”是真实企业盖章件——**本项目没有就写“拟申请/已提交”，不要伪造盖章件**。
