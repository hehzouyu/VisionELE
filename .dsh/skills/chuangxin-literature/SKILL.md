## 写作时怎么用

**文献综述 / 相关工作**按「由近到远、由专到泛」四层组织：

1. **领域现状（直接相关，F 组）**：绝缘子缺陷检测做到了哪一步——雨天场景、轻量化、CA 类注意力、小目标与数据不足三大挑战，先说领域缺什么。
2. **方法支撑（A/B 组）**：检测与决策的算法底座——图学习小样本（A 组）支撑"缺陷样本稀少也能学"；多目标优化（B 组）支撑"精度-速度-体积-路径"的权衡。
3. **工程手段（C/D 组）**：代理模型与降维——轻量化、超参搜索、特征压缩。
4. **跨界启发（E 组）**：只在一句话里点出方法论迁移，别展开。

**G 组是"技术出处层"**：不按综述分层写，而是当报告里出现具体模块名（CA、YOLOv12、RFA、WDCNN、GAT/ChebNet、EdgePool、VMD、cDCGAN、原型网络、MMD、DANN、A\*、DWA）时，逐个挂上出处引用。写技术方案/创新点说明时，每个自研模块必须能追到 G 组里的一篇。

**引用纪律**：
- 正文用上标数字 `[1]`，文末按引用顺序列参考文献，格式见 citations.md。
- 只引你真正读过并写进论证的文献，不要凑数。
- 论文的结论是"别人家的数据"，写进报告时用"已有研究表明"而不是"我们证明了"。
- 英文文献照录标题与期刊名，不要翻译；中文文献用中文。
- G 组经典文献（CA/GAT/ChebNet/A*/DWA）只引用原始出处一次，不要重复堆引用。
- 注意区分两套方案口径：方案企划书（计划书）里是 YOLOv12 + CA + A\*+DWA，技术设想里是 MSA-GCN 半监督进阶方案——引用时对应各自的出处，别把技术设想的论文挂到企划书的模块上。

## 与本项目软模块的衔接

- **视觉模块**：企划书口径（CA + YOLOv12 + RFA，G 组）是基础方案；F 组是领域现状与同行对标；技术设想口径（MSA-GCN 半监督 + WDCNN + cDCGAN + 原型网络 + MMD，A/G 组）是进阶方案。
- **决策模块**：A\* + DWA（G 组 [30][31]）是路径规划与避障的算法出处；B 组四篇是"约束与多目标"的算法底座。
- **轻量化/部署**：C/D 组提供"用更少评估换来可接受近似"的理论依据。
- **不涉及**：电气信号采集链路（泄漏电流/紫外脉冲）属于硬件与信号处理，本 skill 只作背景引用，不作为论证主线（用户分工是视觉 + 决策）。

## 常见错误

- 把 31 篇全塞进综述开头——按主题分层，每层 2-4 篇就够
- 引用只有标题没有结论（"某某提出了某某方法"就完了），必须带一句"它解决了什么/达到什么指标"
- 混淆"代理模型"与"深度学习模型"（前者是逼近昂贵函数的近似器，不是网络本身）
- 把 F 组综述（[16]）当作方法引用——综述只能支撑"现状与挑战"，不能支撑"我们用了它的方法"
- 把技术设想的论文（MSA-GCN/原型网络/MMD）挂到企划书口径的模块上——两套方案各自引用各自的出处
